# 全文剪藏的存储规则

## 路径

优先读取当前项目的 `.local/paths.md`，取得 `$OUTPUT_DIR` 与 `$STAGING_DIR`。缺失时询问用户；不要猜路径，也不要把成品静默写进 skill 或仓库目录。

每次任务在 `$STAGING_DIR` 下建立唯一的 `$JOB_DIR`。下载物、音频、字幕、转写稿、元信息与探针都只放这里；用户原始文件不得移入 `$JOB_DIR`。

## 成品命名

- 全文：`YYYY-MM-DD_中文标题.md`；优先用内容发布日期，无法取得时再使用用户确认的日期或整理日。
- 知识卡片：`中文标题.md`，通常 5–15 个字。
- 文件名移除 `/ \\ : * ? " < > |`；同名不覆盖，先询问或加编号。

## 写入前查重

有原文链接时，用链接中的稳定 ID 或完整 URL 搜索 `$OUTPUT_DIR` 内现有 Markdown。命中后暂停，询问覆盖、另存或放弃。无链接时不猜 ID。

## 中间产物与清理

- 成功：确认成品已经写入并通过完整性校验后，先查看 `$JOB_DIR` 内容；若只有本任务生成的文件，可将整个目录移到废纸篓。
- 失败：完整保留 `$JOB_DIR`，报告路径、已完成部分和可复用文件。
- 只处理自己本轮创建的 `$JOB_DIR`；绝不批量清理 `$STAGING_DIR`，绝不删除用户源文件。
- 个人录制内容不可复得，一律原地保留。

若用户明确允许移动可重新获取的公开源文件，仍应在成品完整、原标题和原文链接已落实后，移动到用户指定的可恢复位置；同名不覆盖，并逐项报告来源与去向。

## 报告

给出成品路径、`$JOB_DIR` 路径、来源与字数/时长、抓取或转写方式、完整性校验结果，以及任何移动或失败事项。
