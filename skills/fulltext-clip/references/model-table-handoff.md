# 模型表交接

仅在同时满足以下条件时，在成品末尾附“拟入表”：

1. 出现明确的模型型号、AI 工具或评测名称；
2. 原文给出了至少一个可复核的硬锚点，例如官方页面、正式公告、技术报告、论文、API 文档、参数量、跑分、上下文、价格或发布日期。

纯观点、行业趋势、模糊系列名或只有营销描述时不提议。剪藏阶段不联网核实，只生成提议，不写表。

```markdown
## 拟入表

拟新增 1 条 / 更新 0 条 / 建议归档 0 条

【新增】<明确型号或工具名>
- 原文给出的硬锚点（未独立核实）：<事实 + 原文出处>
- 冲突或缺项：<原文自相矛盾、说法含糊或没给的关键项>
- 价值：<为何值得记录>
- 来源：<标题、链接、发布日期、发布方>

是否确认交给 model-table 处理？
```

用户确认后，由模型表流程重新查重、核验、备份、写入并回读。

收尾代理除了在成品末尾写“拟入表”，还在任务目录写一份 `proposal.json`（每条：动作、名称、原文给出的硬锚点、冲突或缺项、来源）。主对话在全部篇目完成后汇总去重，一次性请用户确认，不逐篇打断。
