# 截图与图片

## 读图

- 接受单张或多张图片（png、jpg、webp 等），用当前环境的读图能力直接看，不需要外部 OCR。
- 多张截图按文件名或编号顺序处理。同一篇长内容的滚动截图，相邻两张常有重叠文字：按重叠部分去重，拼成连续全文，不重复也不漏段。
- 同一页随动画逐步出现的多张截图，以最终完整版为准；中间状态若有最终版没有的信息，在对应处注明。
- 当前模型或智能体看不了图时：说明哪些图没读，请用户提供文字版；不猜图中内容，也不出成品。

## 提取规则

1. **文字**：逐字转录全文，不是摘要；保留原有结构（标题、列表、引用、段落、加粗）；看不清的字标 `〔?〕`，不靠语感补全。
2. **图表**：转成一个〔图表〕块：标题、类型、能读出的数据（整理成表格）、一句话结构描述；流程图、架构图写清箭头方向和连接关系。密集图表或小字看不清时，用原始分辨率文件，必要时在任务目录的副本上裁切放大局部再读（如 macOS 自带的 `sips`），不改用户原图。仍读不清的数值不编造，标 `〔?〕`。
3. **照片、插图**：用占位符〔图N：一句话描述〕。必须保留原图才看得懂的，先问用户是否存图，确认后再存。
4. **去界面噪音**：状态栏、电量、输入框、推荐位等界面元素去掉，只留内容本体；聊天记录截图保留说话人标识和消息顺序，点赞转发数挪到补充细节。
5. **来源**：从可见线索（平台界面特征、账号名、可见标题）推断来源；判断不了就写“来源：截图（未注明）”，不猜。

## 成品

- 提取后不到 3000 字：按 card.md 做知识卡片。
- 3000 字以上按全文：运行 `prep.py init --input <图片或图片目录>` 取得任务目录（状态 NEEDS_VISION，`meta.json` 里有图片清单），把整理好的正文写进 `out/001.md`（按 write.md 的正文规则：英文截图同样做英中对照，下划线画重点），写 `sheet.json`（`content_type` 为文章、`mode` 为整理，其余字段见 survey.md），再按 finish.md 写补充细节、拼装、检查、发布。

只保存成品本体，不额外留截图原图（除非按上面第 3 条经用户确认要存图）。
