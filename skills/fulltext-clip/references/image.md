# 截图内容提取(模式 C)

## 输入处理

- 接受单张或多张图片(png/jpg/webp 等),直接用 Read 工具查看,无需外部 OCR
- **多张截图**:按文件名/编号顺序处理。若是同一篇长内容的滚动截图,相邻两张之间通常有重叠文字——通过匹配重叠部分去重,拼接成连续全文,不要重复也不要漏段
- **逐步出现的画面**:同一页随动画逐步出现的多张截图,以最终完整版为准;中间状态若有最终版没有的信息,在对应处注明
- **看不了图时**:若当前模型或智能体无法查看图片,说明哪些图没读,请用户提供文字版;不猜图中内容,也不出成品

## 提取规则

1. **文字**:逐字转录,全文而非摘要(红线同 SKILL.md);保留原有结构——标题、列表、引用、段落、加粗;看不清的字用〔?〕标注,不要靠语感补全
2. **图表**:转写为一个〔图表〕标记块,内含:图表标题、类型(柱状/折线/饼图等)、能读出的数据(整理成 Markdown 表格)、一句话结构描述;流程图/架构图写清箭头方向和连接关系。密集图表或小字看不清时,用原始分辨率文件,必要时在 `$JOB_DIR` 的副本上裁切放大局部再读(如 macOS 自带的 `sips`),不改用户原图。仍读不清的数值不编造,标〔?〕
3. **照片/插图**:用占位符〔图N:一句话描述〕;**必须保留原图才看得懂**时按 `storage.md` 先问用户是否存图,确认后再存
4. **去界面噪音**:状态栏、电量、点赞转发数、输入框、推荐位等 UI 元素一律去除,只保留内容本体;聊天记录截图保留说话人标识和消息顺序(点赞/转发等互动数可挪到「补充细节」)
5. **来源推断**:从截图可见线索(平台 UI 特征、账号名、可见标题)推断来源,写入「背景信息」;无法判断时如实写「来源:截图(未注明)」,不要猜测来源

## 完成后

进入共同流程:按 `optimize.md` 优化(英文截图同样做英中段落对照,并视情况补「背景信息/补充细节」),再按 `storage.md` 写入 `$OUTPUT_DIR`。写入时按文章化排版规则组织,不要只堆逐行转录。

只保存最终笔记本体,不额外留截图原图(除非按上述第 3 条经用户确认要存图)。
