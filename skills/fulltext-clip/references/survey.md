# 查询代理：写工作单

这一步在写作之前，产出一张工作单 `sheet.json`，让后面每个写作代理用同一套人名、专名和格式。要查的东西集中在这一步一次查完，写作过程中不再零散联网。

## 读什么

每篇只读这些，不读全文：

- `meta.json`：标题、链接、来源、发布时间、时长、节目简介、平台章节、互动数；
- `stats.json`：档位建议、字数、疑似识别错误的小写英文词（`lower_latin`）、说话人标签的发言占比和各自开头几句（`labels`）、查重结果（`related`）；
- `source.md` 开头约 3000 字（只读前面一部分）；
- 需要时再读 `.local/reader.md`（读者背景，决定哪些词要解释）。

派给你同一节目的几篇时，一起读、一起判断，节目名、主持人、固定栏目一次认准。

多人活动（见面会、圆桌）的嘉宾介绍常常散在全文，只读开头认不全人。这时按 `stats.json` 里每个标签第一次出现的段号（`labels.*.first_seg`），或搜索“有请”“我是”“欢迎”等换场用语，定位那几段前后去读，仍然不通读全文。

## 做什么

1. **内容类型** `content_type`：单人、采访、对谈、讨论、文章。
   - 有平台标签时看占比：一方发言占比明显低（约 25% 以下）且多为提问，是采访；两人相当是对谈；三人以上是讨论。一个主持人带几位嘉宾的圆桌也算采访。
   - 没有标签时看简介和开场：“今天的嘉宾是……”“和我对谈的是……”。
2. **说话人名单** `speakers`：每项写 `label`（平台标签代号 L1、L2……，没有标签就写 null）、`name`、`role`（host、guest、speaker）、`confirmed`、`evidence`。
   - 只有证据确凿才 `confirmed: true`：本人自我介绍、被点名后接话、简介写明且和内容对得上。证据写进 `evidence`。
   - 没把握就 `confirmed: false`，脚本会把这一位显示成“说话人N”。标错比不标更糟。
3. **说话人模式** `speaker_mode`：单人和文章写 none；没有平台标签写 host_only（写作时只给能确定的主持人提问加 🎙️）；有平台标签写 labels；用户明确要求区分说话人才写 requested。
4. **专名表** `terms`：从标题、简介、章节、开头和 `lower_latin` 里整理人名、节目名、产品名、书名、术语的正确写法，写成 `{"wrong": "识别出的写法", "right": "正确写法", "evidence": "依据"}`。只收有依据的；猜不出正确写法的不收，留给写作代理标 `〔?〕`。
5. **查证的边界**：只查影响全篇理解的东西，即节目名、主持人和嘉宾的身份、反复出现的产品名、缺失的元信息。次要细节（嘉宾的社交账号、周边链接、一次性提到的名字）不查，留给写作代理标 `〔?〕`。一般十来次搜索就够，明显超过时停下来收尾。
6. **元信息补全**：
   - `meta.json` 已有的发布时间、原标题、原链接、来源直接用，不重复查。发布时间一律写北京时间的 YYYY-MM-DD。
   - 缺失时（本地文件尤其常见）才联网查：用原标题、作者、内容里独特的原话去搜，定位到原视频、播客或文章，核实后填入真实的标题和链接。
   - 核实不到写“未注明”，不用线索反推一个标题或链接。App 封闭平台（小红书、视频号、抖音等）的内容基本搜不到，不硬搜；看不出平台和作者时，在回复里写明“需要问用户”，由主对话最后一起问。
7. **相关内容** `related`：`stats.json` 里脚本找到的相似旧笔记，加上简介或开场提到的上一期、下半场等，写成 `{"title": "…", "url_or_file": "…", "why": "上一期"}`，给收尾代理写进补充细节。
8. **档位** `mode`：整理、精修或翻译。一般照 `stats.json` 的建议；干净的文章被判成精修、或英文字幕其实是自动字幕时，改过来。英文需要连英文一起整理时写 `"en_needs_cleanup": true`。
9. **背景表用的几行字**：
   - `title`：原标题，英文内容保留英文；
   - `title_zh`：文件名用的中文标题，中文内容一般就用原标题，英文内容译成简洁的中文；
   - `source_line`：平台、作者、节目、期数，如“播客《不束高阁》第 80 期 · 小宇宙”；
   - `published`：YYYY-MM-DD 或“未注明”；
   - `url`：原链接，没有就写空字符串；
   - `speakers_line`：每人一句话身份，并说明正文怎么标。例如“主持 Koji（《十字路口》主理人）；嘉宾 于红（兔咚咚创始人）。正文里 🎙️ 开头的段落是主持人的话”；没有平台标签时写“原稿不区分说话人，只有能确定的主持人提问标了 🎙️”；单人内容写“主播 Elijah（体能教练）”。
10. **给写作代理的话** `notes`（可选）：比如“开头 3 分钟是赞助口播，按略去处理并记入笔记”。

## 产出

写 `sheet.json`，然后在 skill 根目录运行：

```bash
python3 scripts/prep.py apply-sheet --job-dir "<任务目录>"
```

它会校验工作单，把平台标签替换成显示标签，生成写作任务 `tasks.json`；整理档会直接把正文放进 `out/001.md`。报错就按提示改工作单再运行。

网页正文没抽全（状态码 PARTIAL）时，先看 `source.md` 里正文从哪段起、到哪段止，运行 `python3 scripts/prep.py select --job-dir "<任务目录>" --from p12 --to p87`，再写工作单。
