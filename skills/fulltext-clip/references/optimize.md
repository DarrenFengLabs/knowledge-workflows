# 文字稿优化与排版规则(模式 A / A-本地 / B 共用)

## 核心约束

**这是优化,不是改写,更不是总结。** 成品必须保留原稿的全部实质内容、观点、论证顺序和说话人语气。清理口头禅后,字数通常为原稿的 85%–95%;若低于 80%,停下来自查是否删多了。

## 优化规则

1. **错字与专名修正(热词思路)**:同音错字、转写错误(如「事变」→「事半」)。专有名词全文统一:人名、产品名、术语第一次出现时确定写法,之后保持一致;转写前若已知专名,优先在 `transcribe.md` 的 `--prompt` 里喂进去(成熟工具靠「热词」纠专名,是性价比最高的一步)。不确定的写法用〔?〕标注原音,不要瞎猜
2. **去口语噪音**:嗯、啊、呃、就是说、对吧、然后然后 / um、uh、you know、like(填充词用法)。但保留有表达功能的口语(反问、强调、情绪词)
3. **修句**:合并破碎句,补全明显的省略主语;不改变句子原意,不替换说话人用词风格
4. **加标点与分段**:原始 ASR/字幕是无标点流,先补标点;再按话题转换分段,每段约 3–6 句;不要一句一段,也不要超长段
5. **结构标记**:
   - 多人内容:保留并统一说话人标记(**主持人:** / **嘉宾名:**)
   - 长稿(> 5000 字):按内容加少量二级小标题帮助导航,小标题用原文话题措辞,不要自己发挥
6. **不做的事**:不加自己的评论、不加「编者按」、不调整观点顺序、不把口语「书面语化」过头(保留讲话感)

## 元信息块:背景信息 / 全文大纲 / 补充细节

正文前后各加元信息块,是补充不替代全文,**有信息才写,缺的省略,绝不编造**。
**统一不写技术/流程细节**(转写引擎、字幕轨错配处理、下载接口、颜色排版、是否消耗额度等)——那是工作过程,不进成品。专名校订/存疑〔?〕属内容准确性,可保留。

**开头·背景信息**(标题之后):
```
## 背景信息
发布时间:2026-06-11。
原标题:[<内容的原始标题;英文内容保留英文原标题>](<可访问的原始 URL>)。
来源:<平台 / 作者 / 频道>。
全文规模:<字数> / <时长>,覆盖完整时长,符合全文预期。
```
发布时间、来源、规模来自 `fetch.md` 的元信息。

**格式以 `storage.md` 为准**:「原标题」写成 markdown 链接、**不单独出「原文链接」一行**(方便用户整行复制到别处笔记)。没有可用链接时(封闭平台、来源未注明),「原标题」退回纯文本,**不要编造链接**。多个链接时主链接包在标题里,其余放标题后的括号说明,格式同样是 `[说明](链接)`。

**注明来源是硬性要求(整理本地文件时尤其)**:发布时间、原标题、原文链接、来源四项尽量补全。本地文件未自带这些信息时,**联网搜索**补全——用原标题、作者、内容里的独特台词/片段去搜,定位到原视频/播客/文章,核实后填入真实的标题与链接。**核实不到就写「未注明」或标〔?〕,绝不用线索反推编造一个标题或 URL 当事实**(见 `../SKILL.md` 事实红线)。

> **App 封闭平台(小红书 / 微信视频号 / 抖音 等)**:这些平台的内容基本不被公开搜索引擎收录——微信视频号根本没有公开网页链接,小红书个人笔记也多在 App 内。对这类内容**不要硬搜 URL**(搜不到是常态,不是搜法问题):`来源` 写「平台·博主名」,`原文链接` 写「App 内查看,无公开网页链接」,`发布时间` 拿不到就「未注明」。若文件名/内容看不出博主与平台,**直接问用户**(用户往往一句话就能给出,如「小红书 思敏（AI产品版）」「微信视频号 任川」),不要瞎猜。

补全来源后，只有用户明确授权时，才可按 `storage.md` 移动可重新获取的公开源文件；个人录制内容永远保留。

**背景信息之后·全文大纲**(紧接其后):按正文实际章节/话题顺序,列出全文骨架,帮助读者快速把握脉络。
```
## 全文大纲
1. **小节主题一**:一句话概括。
2. **小节主题二**:……
```
长稿(章节多)可适当归并成若干主线条目,不必逐个小标题罗列。

**结尾·补充细节**:视觉元素(封面/关键插图/画面图表,读不清别硬描述)、互动数据(取 yt-dlp 的 `like_count/repost_count/comment_count/favorite_count`,拿不准标〔?〕)等。

## 全文重点(下划线,所有模式)

把**全文重点**在**正文内**用 `<u>…</u>` 下划线标出(中文为主稿标中文那句)。

## 英文稿:翻译 + 英中对照排版

适用:原始内容为英文(或英文为主)。**模式 A / A-本地 / B 同样执行。** 流程:先优化英文原稿 → 逐段翻译 → 对照排版。

排版(逐段交替,**英上中下**;英文降视觉层级):
- 英文原文用 `<small>…English…</small>`——字号小、作对照参考,放上面
- 中文译文用正文默认样式,放下面(主体)

```
### Section Title / 小节标题

<small>English paragraph one, optimized.</small>

英文第一段的中文译文。

<small>English paragraph two, optimized.</small>

英文第二段的中文译文。
```

翻译规则:
- 准确优先于流畅;不省略、不过度意译
- 术语:通行英文术语保留并首次括注中文(如「fine-tuning(微调)」);有公认中文译名的用中文
- 若当前项目有 `.local/reader.md`，按其中的读者背景决定术语解释、符号与拆分方式；没有时不要擅自假设具体个人偏好
- 说话人标记只标一次,**标在中文段开头**(中文是主体),如 `**主持人：** …中文…`
- 长难句可拆译,但信息不增不减;「背景信息/本文重点/补充细节」用中文即可,不必双语

## 长稿处理(> 2 万字)

分段处理时,每段开始前先重读本文件规则 + 上一段末尾 200 字(保持术语和风格连续);全部完成后做一遍全文术语一致性检查。

## 输出

优化完成后,按 `storage.md` 写入本地 `$OUTPUT_DIR`。
