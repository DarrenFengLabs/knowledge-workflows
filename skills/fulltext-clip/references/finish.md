# 收尾代理：大纲、术语、补充细节、检查与发布

正文已经由写作代理（或整理档里由脚本）放进 `out/`。你负责正文前后的部分，跑检查，定点修正，然后发布。不读全文，也不联网。

每多调用一次工具，模型就要把到这时为止的全部上下文重读一遍；收尾在最后，上下文最大，所以尽量少几轮：要看的东西一次看完，要改的一次改完。

## 读什么

在 skill 根目录运行一次：

```bash
python3 scripts/assemble.py digest --job-dir "<任务目录>"
```

它把要用的材料压成一屏：工作单要点、互动数和跳过的图片、各块小标题、各块笔记（概括、术语、存疑、改正、略去的内容）、全部〔?〕及上下文、断在句中的接缝、读者画像（决定哪些词要解释）。不要再逐个打开这些文件；要细看某处，只读那几行。

- 一个代理做完全篇时没有笔记文件：大纲、术语、改正按你写正文时的掌握写，用 digest 里的小标题和〔?〕清单核对。
- 整理档（digest 会注明）还要读 `out/001.md`：正文由脚本原样搬入，你在上面画下划线、删去与正文无关的引导语（关注、星标、二维码之类），并改个别错字。只做精确的局部替换，不整篇重写。

## 写 header.md

```
## 全文大纲

1. **主题一**：一句话概括。
2. **主题二**：……

## 术语速查

| 词 | 解释 |
| --- | --- |
| Agent（智能体） | 能自己拆任务、连续调用工具、多步完成目标的 AI 程序 |
```

- 全文大纲：正文超过 3 千字时写。按各块小标题和笔记 `sections` 的顺序合并成 5–10 条；长稿归并成几条主线，不必逐个小标题罗列。
- 术语速查：有读者可能不懂的词时写，按 `.local/reader.md` 的口径一句话解释；官方链接可以并进解释。与背景信息重复的不写。没有就整节省略。

## 写 tail.md

```
## 补充细节

- **略去的内容**：……
- **相关内容**：……
- **整理说明**：……
```

每项以加粗的短标签开头，有信息才写：

- **略去的内容**：赞助口播、录制前后的闲聊等，写明大致位置（来自笔记 `omitted`）。
- **相关内容**：工作单 `related` 里的上一期、下半场、相似旧笔记。输出目录里的旧笔记写成 `[[文件名去掉 .md]]`，外部内容写成 `[标题](链接)`。
- **视觉元素**：图片、图表、画面里的关键内容；读不清的不硬描述。整理档里脚本跳过的无说明图片，写“原文有 N 张图片，未收录”（`meta.images_skipped`）。
- **互动数据**：`meta.interaction` 里的播放、点赞、评论、收藏数，照抄数字，注明取数日期。
- **存疑之处**：汇总各块的 `doubts`，说明为什么存疑。
- **整理说明**：原文从哪来（平台字幕、本机转写、妙记逐字稿、网页正文），说话人怎么处理的，改正了哪些主要识别错误（从各块 `fixes` 里挑有代表性的）。不写转写引擎、下载接口这类过程细节。

出现“明确的模型或工具名 + 至少一个可复核硬锚点”时，按 [model-table-handoff.md](model-table-handoff.md) 在 tail.md 末尾加 `## 拟入表`，同时写 `proposal.json`。只提议，不写表。

## 存疑不再查

〔?〕原样保留，汇总进“存疑之处”。专名在查询那一步已经统一过；到收尾再联网，查到的多半是顺口一提的次要细节，而此时上下文最大，每搜一次都最贵。读者需要时自己去核。

## 拼装、检查、修正、发布

在 skill 根目录依次运行：

```bash
python3 scripts/assemble.py build --job-dir "<任务目录>"
python3 scripts/check_clip.py --job-dir "<任务目录>"
```

两条命令放在同一次调用里跑。检查报出的问题按行号定点修：读报出的那几行附近，用精确替换改，所有问题在一次调用里改完。改的位置是源头文件（`out/NNN.md`、`header.md`、`tail.md`），不要直接改 `final.md`，因为重新 build 会覆盖它。改完重新 build、check，最多两轮。

- “违规”必须修掉；“提醒”看一眼，确实需要才改（比如下划线偏少就补画）。
- 某块在句中结束时（digest 已列出接缝两边的文字），把断开的句子接回一句（改两边的 `out/` 文件）。
- 两轮后仍有违规：不发布，回报违规项，由主对话决定。
- 检查通过后发布：

```bash
python3 scripts/assemble.py publish --job-dir "<任务目录>" --output-dir "<成品目录>"
```

输出目录已有同名文件时脚本会拒绝写入（退出码 3）：不要覆盖，回报给主对话，由用户决定覆盖、另存还是放弃。

## 回复

只回几行：成品路径（或未发布的原因）、规模、说话人怎么处理的、〔?〕 几处、检查结果、拟入表几条、需要用户确认的事。

## 背景信息表

背景信息表由脚本生成，不要手写；要改里面的字，改工作单再 build。
