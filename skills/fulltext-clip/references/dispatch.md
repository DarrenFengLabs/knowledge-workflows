# 主对话：分派与汇总

主对话只做三件事：准备、派活、汇总。原文和成品全文都不读，只看脚本的一行摘要、`prep.py status` 的状态表和子代理回来的几行回复。这样每篇都在干净的上下文里处理，质量稳定、可以并行，一篇出错不影响其他篇，主对话也不会越跑越长。

单篇也这样派；只有短摘录和单张截图由主对话直接做（见 card.md、image.md）。

## 开工

0. 批量放在新开的对话里跑，跑完就结束：主对话越长，每派一次活、每收一条回报都要把整段对话再处理一遍，本身就很耗额度。
1. 读 `.local/paths.md`，取 `OUTPUT_DIR`、`STAGING_DIR`；缺了就问，不猜。下文 `<SKILL_DIR>` 指本 skill 的根目录（`SKILL.md` 所在目录），脚本都在这里运行。
2. 在 `$STAGING_DIR` 下建本批目录，如 `2026-09-30_小宇宙5篇/`，每篇一个子目录（`01`、`02`……）作为任务目录。
3. 在本批目录写 `progress.md`：完成条件（逐篇剪藏、各存一份到输出目录、检查零违规、失败篇目记录原因、需要用户确认的事最后一次性问）和篇目清单。每做完一波，把 `prep.py status <本批目录>` 的输出贴进去；上下文被压缩后，读它和本文件就能接着做。

## 按波次走

**第 1 波 · 准备（脚本）。** 每篇运行：

```bash
python3 scripts/prep.py init --input "<链接或文件>" --job-dir "<任务目录>" --output-dir "$OUTPUT_DIR"
```

要转写的音视频放后台跑（脚本会自动排队，本机一次只转一篇）；文字类几秒就好，先往下走。按每篇最后一行 JSON 的状态码处理：

| 状态码 | 处理 |
|---|---|
| OK | 进入查询 |
| PARTIAL | 照常查询，查询代理会先用 `prep.py select` 截取正文 |
| DUPLICATE | 这一篇先停下，记进“要问用户的事”（覆盖、另存还是跳过） |
| NEEDS_VISION | 图片或扫描件，按 image.md 处理，可以派一个子代理专门看图 |
| NEED_LOGIN、BLOCKED、NEED_UPGRADE、UNSUPPORTED、PAID、NOT_FOUND、NO_TEXT | 按 fetch.md 的平台表排障或兜底搜索；要用户动手的（登录、导出文件）记下最后问 |
| TRANSCRIBE_FAILED | 看任务目录 `asr/` 里的日志，按 transcribe.md 处理 |

**默认一篇一个代理。** 正文约 3 万字以内（大约两小时以内的音频；英文约 1.5 万词以内）的篇目，派一个 `clip-solo` 代理从头做到尾：写工作单、按块依次写正文、收尾、发布。每个代理都要重新加载规则和上下文，拆给查询、写作、收尾几个代理，这部分固定开销就付了几遍；2026-10 实测，1.2 万字的稿子一个代理做完约 10 万 token，拆成 4 个代理约 23 万，质量相同。

**超过约 3 万字的长稿才拆开：**

- 查询：同一节目、频道或作者的几篇交给同一个查询代理（每个最多 5 篇）。
- 写作：每个写作代理负责连续的 2–3 块（约 2–3 万字），按块依次写，不是每块一个代理。
- 收尾：每篇一个收尾代理。

同一时间最多 3 个子代理在跑。额度按时段计，并发太多会很快撞上上限，打断正在跑的代理，已经花掉的就白费了。

已经准备好的篇目先往下走，不必等后台转写全部完成。宿主不支持子代理时，按同样的顺序自己依次做，每步只读该步的角色说明和它列出的文件。

## 派活提示

用宿主的子代理功能，按角色名派：`clip-solo`（一篇做到底）、`clip-survey`（查询）、`clip-writer`（写作）、`clip-finish`（收尾）。本仓库在 `.claude/agents/` 和 `.codex/agents/` 预置了这四个角色（模型档位在那里配）；其他宿主用通用子代理，把下面的提示原样发过去。

任务消息里写明两件只有主对话知道的事：用户是否要求区分说话人、是否要求双语（中英对照）。没提到就都写“否”，英文内容默认只出中文。

查询：

```
你是 fulltext-clip 的查询代理。先读 <SKILL_DIR>/references/survey.md，照它做。
任务目录（同一节目，一起判断）：
- <任务目录1>
- <任务目录2>
用户是否要求区分说话人：否
用户是否要求双语：否
脚本在 <SKILL_DIR> 里运行。完成后按 survey.md 的“回复”写几行。
```

写作（长稿）：

```
你是 fulltext-clip 的写作代理。先读 <SKILL_DIR>/references/write.md，照它做。
任务目录：<任务目录>；你负责第 <NNN>–<MMM> 块（见 tasks.json），按顺序一块写完再写下一块。只读这几块和工作单。
完成后回复一两行。
```

收尾：

```
你是 fulltext-clip 的收尾代理。先读 <SKILL_DIR>/references/finish.md，照它做。
任务目录：<任务目录>；成品目录：<OUTPUT_DIR>。脚本在 <SKILL_DIR> 里运行。
完成后按 finish.md 的“回复”写几行。
```

一篇一个代理做完（默认，`clip-solo`）：

```
你是 fulltext-clip 的剪藏代理，这一篇从头做到尾。依次读 <SKILL_DIR>/references/ 下的
survey.md、write.md、finish.md，照它们做：写工作单并运行 apply-sheet → 写正文（整理档跳过；不写笔记）
→ 收尾、检查、发布。
任务目录：<任务目录>；成品目录：<OUTPUT_DIR>。脚本在 <SKILL_DIR> 里运行。
用户是否要求区分说话人：否
用户是否要求双语：否
完成后按 finish.md 的“回复”写几行。
```

子代理回复里提到“需要问用户”的，记进本批的“要问用户的事”，不中途打断用户。

子代理因宿主的临时故障没做完（比如交回了写好的工作单内容却没能落盘），先核对它交回的内容和脚本取到的元信息是否一致，再重派或由主对话接手这一步。子代理被拒绝的操作，主对话不换个身份替它做，报告给用户。

## 汇总

全部做完后运行 `python3 scripts/prep.py status "<本批目录>"`，给用户一张表：

| # | 标题 | 结果 | 成品 | 规模 | 说话人 | 〔?〕 | 需要你决定 |
|---|---|---|---|---|---|---|---|

- 宿主能看到子代理的 token 用量和耗时，就逐篇记进 `progress.md`，报告里给总数。
- 然后一次性列出要问用户的事：重复成品怎么处理、同名冲突、需要登录或手动导出的篇目、各篇“拟入表”提议的汇总（用户确认后交给 model-table）。
- 清理按 storage.md：成功的任务目录可移到废纸篓，失败的保留并给出路径。本批目录等所有问题处理完再清。
