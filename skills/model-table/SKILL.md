# AI 模型表维护

这是显式的结构化维护流程。**看到模型信息不等于获得写入授权**；写入必须经过用户确认，并保留可恢复备份。

## 开工配置

若当前项目存在 `.local/paths.md`，先读取其中的 Base、表、视图 ID 与 `$STAGING_DIR`。若存在 `.local/verified-facts.md`，将其作为带时效的事实缓存读取；过期价格和榜单必须重新核实。缺少必要 ID 或路径时询问用户，不猜占位值。

事实纪律见 [references/source-integrity.md](references/source-integrity.md)。

## 何时执行

- 用户明确要求更新、入表、维护、订正或归档；
- 用户确认了内容处理流程给出的“拟入表”条目。

纯观点、行业分析、普通问答，或只有型号名而没有硬锚点时，不启动写表。可解释尚缺哪些信息，但不要创建空壳记录。

## 强制流程

1. **解析意图**：新增、更新、订正或建议归档；确认对象与范围。
2. **查重**：先按名称和相近后缀查询现有记录。基础版、Flash、Pro、Next 等必须视为不同对象，除非一手资料明确等同。
3. **核实**：至少有一个可复核硬锚点；每个数值都要能追溯到适用该型号的来源。
4. **形成预览**：逐条列出动作、字段变化、依据、未核实项和可能影响。
5. **等待确认**：用户可以只确认部分条目。未确认的保持提议状态。
6. **备份**：将涉及的表导出为 JSON 与 CSV，写入 `$STAGING_DIR/base备份/base-backup-YYYYMMDD/`；不得写入笔记输出目录。
7. **写入**：只执行已确认的变更。
8. **回读校验**：重新读取写入记录，逐字段对照预览；失败时停止后续写入并说明可恢复方式。
9. **报告**：列出新增、更新、归档数量，每条字段变化、备份路径和回读结果。

## 红线

- 参数、跑分、上下文、价格、日期和模态一个都不能猜；查不到就留空并标“未核实”。
- 归档前先确认判据适用，并把旧记录独有的可复述锚点转移到取代项。
- 版本演进通常是新增新行并关联旧行，不覆盖历史版本。
- 备份失败即不得写入；写入后回读失败即不得报告成功。
