# 飞书授权（lark-cli）

模型表所在的飞书多维表格要用 lark-cli 以用户身份读写。本文说明授权能维持多久、怎么一次授够、失效后怎么恢复。命令细节以 lark-shared skill 和 `lark-cli auth <子命令> --help` 为准。

## 授权能维持多久

用户身份靠两张凭证。下表数值出自飞书开放平台《刷新 user_access_token》文档（2026-09-28 核对），文档注明都不是固定值，以接口实际返回为准：

| 对象 | 有效期 | 到期后 |
|---|---|---|
| 访问凭证 `user_access_token` | 约 2 小时（示例 7200 秒） | CLI 用刷新凭证自动换新，用户无感 |
| 刷新凭证 `refresh_token` | 示例 604800 秒，即 7 天（本机实测相同） | 每张只能用一次，换新时发一张新的；过期后只能重新授权 |
| 用户授权本身 | 365 天 | 满期后必须重新授权，续期绕不过去 |

所以“长期授权”的实际做法是：一次授够要用的业务域，然后在刷新凭证到期前至少用一次用户身份，让凭证一环接一环续下去，最长到 365 天。做不到永久免授权。长时间没有任何 `--as user` 调用时，CLI 会报 `refresh_token expired ... clearing` 并清掉本机凭证，只能重新授权。

换新后的刷新凭证是否重新计满有效期，官方文档没有明说。365 天上限的存在说明它是滚动续期，但还没实测：访问凭证过期后再用一次用户身份，对比前后的 `refreshExpiresAt` 是否后移。确认之前，不要把“用一次就再保 7 天”当作确定事实告诉用户。

## 标准流程

1. **体检。** 运行 `lark-cli auth status --json`，看 `identities.user.status`。显示可用或 `needs_refresh` 时直接干活（`needs_refresh` 会在下次调用时自动刷新）；显示 `missing`、`expired`，或调用时报缺权限，进入第 2 步。
2. **发起授权，一次授够。**

   ```bash
   lark-cli auth login --domain base --no-wait --json
   ```

   业务域一次写全，免得之后因为缺某项权限再打断用户一次：`base` 覆盖查询、备份、写入和回读。项目说明（如 AGENTS.md）给了统一清单时以它为准。重新授权时也写全，不依赖上次授权残留的权限。

   `--domain` 会连带申请该域的写入和删除权限（2026-09-28 实测：`base` 域含删除数据表、删除记录等）。只读用途想收窄时，改用 `--scope` 逐项列出只读权限；已授出的权限 CLI 不能单独撤销，要用户在飞书的授权管理页整体取消后重新授权。
3. **交给用户确认。** 把返回的 `verification_url` 原样给用户，不改编码、不加标点。lark-shared 要求同时给二维码：先进入 `$STAGING_DIR`，再运行 `lark-cli auth qrcode "<verification_url>" --output auth-qr.png`（该命令只接受相对路径），把图片路径给用户，方便用手机飞书扫码。说明链接的有效时长（以返回的 `expires_in` 为准，实测为 600 秒），请用户授权后回复一声，然后结束本轮，不在同一轮里等待。宿主能在本轮中途显示消息、又支持后台命令时（如 Claude Code），也可以先把链接发给用户，再把第 4 步的命令放到后台运行：它最长轮询约 10 分钟，用户一授权就自动完成，不必等用户回复（2026-09-28 实测可行）。不要反复重新发起授权，每发起一次，上一个链接就作废。
4. **完成登录。** 用户回复后，由你执行 `lark-cli auth login --device-code <device_code>`。链接已过期就回到第 2 步重新发起，不复用旧的 `device_code`。结果若提示“以下请求 scopes 未被授予”并以非 0 退出（实测为 3），其余权限其实已经生效：按第 5 步确认状态，不要重试。
5. **验证并告知期限。** 运行 `lark-cli auth status --json --verify`，确认 `identities.user.status` 为 `ready`。同一节里 `refreshExpiresAt` 是刷新凭证截止时间，`expiresAt` 是访问凭证到期时间，`grantedAt` 是授权时间（加 365 天就是最晚必须重新授权的日子）。把 `refreshExpiresAt` 换算成日期告诉用户：在这之前用一次飞书功能即可续期。2026-09-28 实测：17:08 授权，`expiresAt` 是 2 小时后，`refreshExpiresAt` 是 7 天后，与官方示例一致。

## 使用中的规则

- 读用户资源的命令一律显式写 `--as user`。本机默认身份是 `auto`，用户凭证失效时会自动落到应用身份；应用身份读不到用户资源时返回空的成功结果而不报错，容易被误当成“没有内容”。
- 不为了让命令跑通而改用 `--as bot`。应用身份只能访问明确分享给应用的资源，和用户身份不是同一份权限；也不要改用网页抓取绕过授权。
- 报错含 `need_user_authorization`、`token_missing`、`refresh_token_expired`、`refresh_token_revoked` 时，回到第 2 步。报错含 `missing_scopes` 并附 `console_url` 时，是应用后台还没开通该权限，把链接原样交给用户去开通，不要反复重新登录。
- 不在终端、日志或成品里输出任何凭证（accessToken、refreshToken、appSecret）。

## 想更省心时（需用户同意）

在本机加一个定时任务（macOS 用 launchd），每隔几天跑一次 `--as user` 的只读调用，就能在 365 天内免扫码。这会改动用户环境，只在用户明确同意后设置。设置前先实测：隔 2 小时以上再调用一次，对比前后的 `refreshExpiresAt` 是否后移，确认续期真的生效。
