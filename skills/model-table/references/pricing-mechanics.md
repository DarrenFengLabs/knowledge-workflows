# 计价机制与不腐坏的结论

> 这份放**机制和结论**，不放具体数字——数字会腐坏，机制不会。
> 具体价格与型号锚点在 `local/verified-facts.md`（本地缓存，不进仓库，有过期规则）。

## ⭐ 最重要的一条：Token 单价 ≠ 任务成本

来源：Databricks 万人规模实测（1.1 万员工、3000+ 工程师真实产出）。

- Sonnet 5 单价比 Opus 4.8 便宜约 **1.7 倍**，但**单次任务成本 $2.09 vs $1.94 反而更贵**，完成率还低 6 个百分点——因为它为完成任务尝试更久、读得更多，**多消耗 1.9 倍 token**
- **Harness 对成本有决定性影响**：同一个模型换框架，**成本差 2 倍以上而质量一致**。差异主要来自每次喂给模型的上下文量

→ **所以模型表如果只记单价，记录的数字没有决策价值。** 这就是「我实测过?」那一列存在的意义，也是判断「这个模型贵不贵」时**不能只看价目表**的理由。

## 计价结构（各家的共性与差异）

| 机制 | 说明 | 影响 |
|---|---|---|
| **缓存倍率**（Anthropic） | 命中 = 输入价 **0.1x**；5 分钟缓存写入 **1.25x**；1 小时写入 **2x** | 重复上下文的场景成本可降一个量级 |
| **Batch 折扣** | 输入输出各打 **5 折** | 非实时任务应默认走 batch |
| **长上下文不加价**（Anthropic 4.6+） | 90 万 token 请求与 9 千 token 同价 | 与下面「分档计价」是相反策略 |
| **长短上下文分档**（OpenAI GPT-5.6） | 同一模型长上下文单价约为短的 **2 倍** | 记价格时**必须注明是哪一档**，只记一个数就是错的 |
| **分时定价**（DeepSeek） | 峰谷价差 **2 倍**。峰值为 UTC 周一至周五 01:00-04:00 与 06:00-10:00 | 可调度的任务挪到谷时直接省一半 |
| **⚠️ tokenizer 变更**（Claude 4.7+） | 换了新 tokenizer，**同样文本约多产生 30% tokens** | **这会抵消一部分降价**。跨代比价时必须算进去，否则「降价了」是假的 |

## 型号家族的结构性知识

- **GPT-5.6 是三档家族**：Sol / Terra / Luna，不是单一模型。只记一行 Sol 会漏掉另外两档，而 Luna 正对应「日常任务分流给轻量档」的省钱做法
- **模型 ID 会失效**：`deepseek-chat` / `deepseek-reasoner` 已从官方文档消失且未标为别名。**入表的 ID 要定期回官方文档验证是否还在售**

## 一条正在成型的行业判断

**独立视觉模型正被通用多模态吸收**，两家大厂的官方动作佐证：

- **阿里**：百炼官方标注 qwen-vl-max / qwen-vl-plus / qwen3-vl-plus「不再作为首选推荐」，**从 Qwen3.5 起用文本档位即可完成视觉理解**
- **腾讯**：官方产品页已无独立 HY-Vision 型号，视觉并入通用多模态；组织上也已把多模态部门与大语言模型部门合并

→ 归档独立视觉模型前先看它是不是被同厂通用模型吸收了——**那属于「被完全替代」，是成立的归档理由**。
