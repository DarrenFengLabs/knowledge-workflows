# 入表口径与归档判据

## 入表口径

- 文档若已把条目分成「模型列表」「产品（评测）」两区，**直接按此分流**到模型表 / 工具表
- 附录里的「已核实的型号事实」表可直接采信（它自己标了来源层级）；**速递三手摘要标「部分核实」**
- **版本升级新增一行，旧行标注被谁取代，不覆盖** —— 演进史本身就是可讲的行业动态
- 若表结构要求人民币，使用任务当日可核查汇率折算，并在硬锚点中同时保留**美元原值、汇率来源与核实日期**；不得沿用无日期的固定汇率
- 「信息来源」累加追加；**同一模型多篇文章 → 就地更新，不新增行**

## 查证顺序（严格按这个来）

1. **表内「官方来源」字段已有的链接** —— 入表时留的一手入口，最准
2. 厂商官方文档 / 产品页
3. 榜单
4. 搜索引擎

> **这条是花了三轮才学会的**：前三轮都在搜索引擎里找，查不到就标待验证。用户提醒「待定条目的『官方来源』字段本身就有链接」——直接抓那些链接，剩下 4 条里 3 条当场解决。

微信公众号链接被风控挡时，可尝试浏览器访问或带常规浏览器 UA 的 `curl -sL`；失败就报告，不伪造原文内容。

## ⚠️ 速递的日期滞后

**速递报道日 ≠ 模型发布日。** 实测两例：Mureka V9.5 速递 08-19 报道、实际 07-19 WAIC 发布，滞后一个月；Grok Imagine Image 2.0 速递 08-11、实际 08-07。**按发布日入表。**

## 价值点的 emoji 标记（去留信号）

| 标记 | 含义 | 判据 |
|---|---|---|
| 📦 建议归档 | 有确证依据可删 | 已下架 / 已被同厂新版**完全**替代（新版价格性能都不差）/ 榜单分数明确落后且无独特叙事 |
| ⚠️ | 保留但有坑 | 数据存疑、名称易混、价格有变、不在 SOTA 但有独特保留理由 |
| 🔍 待验证价值 | 无硬锚点未核实 | **没查过不等于没价值，不可据此直接删** |

emoji 必须与「状态」字段一一对应（已归档↔📦、待定↔🔍），**写入后要跑一致性校验**。

## ⛔ 标 📦 前必须先确认判据本身适用

2026-09-02 实测：**一次性错判 3 条**，根因都是「用错了判据还照样下结论」。三种典型错法：

1. **榜单版本 / 赛道选错** —— 混元 HyOCR-1.5 被判「未进 OmniDocBench v1.5 前列」，实际它在 **v1.6 端到端赛道第一（94.74）**。既看错了榜单版本，又把「端到端」与「两阶段级联」两个赛道混为一谈
2. **判据对象不匹配** —— 用 OCR 榜判断 SenseNova-Vision-7B-MoT，但它根本不是 OCR 专用模型，是融合 6 项任务的统一视觉模型
3. **页面类型看错** —— GLM-Realtime 标「官方发布页查不到」，实际那是**新品发布页（只列新品）**，模型文档页有完整 API 规范与定价，它一直在售

> **「我查过了」若判据错了，比「我没查」更危险——它带着虚假的确定性。**

## 归档机制

- 「状态」单选：`在用` / `已归档` / `待定`
- 主视图筛 `状态 != 已归档`；归档视图筛 `状态 == 已归档`
- **归档 ≠ 删除**

### 归档前必须做「锚点转移」

待归档记录若带着**独有的可复述数据**，先追加到取代它的那条的硬锚点里，格式 `【承自 X，归档转移】…`，**回读校验通过后才改状态**。

已完成的转移示例（4 条）：Grok 4.5 的 token 效率对照 → Grok 4.6；GLM-5.2 的 Databricks 实测 → GLM-5.3；Qwen3-TTS 的 3 秒克隆+97ms → Qwen-Audio-3.0-TTS；Fable 5 的 tokenizer +30% → Fable 5.1。

## 取代链：两个字段，成对写入

- 「被谁取代」`<field_id>`（归档视图显示）：本条被谁取代
- 「历史版本」`<field_id>`（主视图、面试速览显示）：本条取代了谁

⚠️ **飞书的自引用双向关联不会自动生成反向列。** 实测：Qwen3.8 Max 被 3 条指向，但它的「被谁取代」是空的。**必须建两个字段并成对写入**；改关系时两边都要更新，用「正向集合 == 反向集合」做校验。

无替代者的不建链，理由写在价值点（如 Sora 2 Pro 产品线关停、豆包 Doubao 无版本号）。
