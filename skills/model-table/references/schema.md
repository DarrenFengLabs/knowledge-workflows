### ⭐ 任务 / 能力 / 关联场景 三者的层次差异

这是解决「看不懂」的关键，已写进字段说明：

- **任务 = 客观**，模型能干什么活（看厂商文档）
- **能力 = 客观**，同类里强在哪（看跑分）
- **关联场景 = 主观**，我什么时候用它（使用者的判断）

**生成类垂类模型「能力」为空是正常的，不是漏填。**

### 「任务」的取值（输入→输出）

文本对话(文→文) · 多模态理解(图/音/视频→文) · 文档解析(文档图→结构化文本) · 文生图(文→图) · 图像编辑(图+指令→图) · 视频生成(文/图→视频) · 语音合成TTS(文→音) · 语音识别ASR(音→文) · 实时语音对话(音→音，端到端) · 音乐生成(文→音乐) · 3D生成(文/图→3D)

> **为什么废掉原「模态」字段**：它名为模态、实装任务，且**方向不明**。最直白的证据——21 条「语音」里 TTS(文→音) 和 ASR(音→文) 方向完全相反却共用一个标签。改成「输入→输出」后自动拆成 TTS 8 / 实时语音对话 8 / ASR 4。

### 模态标注的三态约定

「任务」字段的空缺**无法区分「不支持」和「没查」**，所以三种情况在硬锚点里分开写：

- 已核实支持 → 打勾 ＋ 硬锚点写「官方模态：输入 text + image，输出 text」
- 已核实不支持 → 不打勾 ＋ 硬锚点明写「模态：纯文本输入」并给依据
- 未核实 → 不打勾 ＋ 硬锚点标「⚠️ 图像输入能力未核实——没打勾是因为没查，不代表不支持」

### ⚠️ 型号系列陷阱（已踩过两次）

`GLM-5.3` vs `GLM-5.3-**Flash**`、`LongCat-2.0` vs `LongCat-**Next**` —— 同系列里多模态型号和本体是两回事，**不可把 Flash/Next 版的能力安到本体上**。查证时必须确认查的是哪个型号。
