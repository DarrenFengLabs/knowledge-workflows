# 主对话：分诊流程

主对话读这份，子代理不读。流程是漏斗：枚举候选 → 摘要预筛 → 抽检 → 读原文定级 → 跨篇综合 → 交付。原则见 SKILL.md，这里写每一步怎么做。

## 开工对齐

从用户输入能确定的直接做；只有会明显改变范围或成本的才问，一次问完：

- 候选集是一次性回溯，还是持续积累？
- 时间范围、来源范围和扫描方向是什么？
- 要周期性导读，还是一次性专题总纲？有没有指定的成品格式（如项目文档）？
- 有没有已有的总纲、偏好画像或一票保留规则？

开工时在 `STAGING_DIR` 下建本次的任务目录，抓到的原文、账本、各批结果、抽检记录都放这里。批量时再写进度文件 `progress.md`：范围、完成条件（如“每批预筛结果都在、条数对得上”）、批次清单和每批状态。每批结果各写一个文件，做完一批就更新进度。上下文被压缩或换了会话，读进度、SKILL.md 和本文件就能接着做，不凭记忆续写。一批失败只记进进度，接着做别的批；要用户定的事做完一起问。

## 候选账本

每个候选一行，写进任务目录的 `ledger.jsonl`（每行一个 JSON）。ID 定下后，后面所有清单都沿用：

| 字段 | 内容 |
|---|---|
| `id` | 稳定序号 |
| `title` | 原标题；核实不了就标出来 |
| `url` | 原文链接优先，聚合页链接次之 |
| `date` | 内容发布日期 |
| `source` | 作者、机构、媒体或栏目 |
| `tier` | 一手 / 二手 / 三手 |
| `summary_from` | 预筛看的是什么：原文摘要、聚合页要点、搜索摘要，或只有标题 |
| `summary` | 预筛用的摘要 |
| `chars_total` | 原文或可用文本的字数，不知道写 null |

聚合页、日报和周报常常只是入口：把它的条目全部列进来，再看同一来源同期有没有它没收的独立长文。

来源分三层：

- 一手：官方公告、技术报告、论文、原始访谈、自产研究。
- 二手：媒体编译、转述或转载。数字和原话用进结论之前，尽量回到一手。
- 三手：日报、速递和搜索摘要，只用来发现线索和预筛。

一手来源也可能有产品立场：成品里把论证证据和商业落点分开写。

## 抓取

优先用稳定的公开页面和结构化字段。微信公众号批量任务可以用 `scripts/fetch_wechat.py`，输入每行写“ID、Tab、链接”，正文就按 ID 存进 `txt/`，和精读代理找的文件名一致。它报“正文未定位”时，说明页面结构变了，停下来报告，不拿空正文或整页文字凑数。

## 本次规则

预筛之前，在任务目录写一份 `rules.md`，预筛和精读的子代理都读它：

- 范围：主题、时间、来源；
- 读者关注什么：从 `.local/reader.md`、`.local/profile.md` 和用户本轮的话里摘，写成判断时用得上的几句；
- 一票保留规则：来自 profile.md 和用户本轮的指令，按顺序编号。每条要有可执行的判据（如“讲成本结构、token 经济的至少读关键段落”），不写宽泛的类别；
- 这批特有的口径：如判重复时参照哪份已收清单，哪一层条目读原文的门槛更高，本批是否只能凭标题预筛。

抽检后新增或修改的规则也写进这份，注明是哪次抽检引出的。

## 分批派活

量大时，预筛每批 50–100 条，精读每批 5–10 篇，各交给一个子代理，在干净的上下文里判断。主对话不读原文全文，只读各批结果、笔记和子代理的几行回复，这样不会因为堆满原文而变慢、变粗。每个子代理只写自己的结果文件，不写账本、进度这些共享文件，合并由主对话做。

预筛：

```text
你是 reading-triage 的预筛代理。先读 <SKILL_DIR>/references/screen.md，照它做。
本次规则：<任务目录>/rules.md
你这批：<任务目录>/batches/<批>.jsonl
结果写到：<任务目录>/screen/<批>.jsonl
```

精读：

```text
你是 reading-triage 的精读代理。先读 <SKILL_DIR>/references/read.md，照它做。
本次规则：<任务目录>/rules.md
你这批：<任务目录>/rbatches/<批>.jsonl（账本里这几条的行，带预筛定的读法）
原文目录：<任务目录>/txt/
结果写到：<任务目录>/read/<批>.jsonl，笔记写到 <任务目录>/notes/
```

每批回来后用 `coverage.py` 合并核对（见“覆盖率”）：条数对不上、有不合规的决定，就退回那一批重做。精读标了 `need_full` 的，由主对话决定要不要改成读全文、再派一次。

## 抽检

预筛做完、读原文之前，从两组里随机抽样，回原文重新判断（拿不到原文就重读摘要）：

- 排除项；
- 定为“只看摘要”的保留项。这一组只凭摘要就放行，误判往往最多：官方的长博客、事故复盘，摘要常常只有一两句。

每组的抽样量：

- 不足 20 条：至少 3 条；
- 20–99 条：至少 10%；
- 100 条以上：至少 10 条，且不低于 5%。

本批只能凭标题预筛的（批次太大、没有摘要），抽样量按上面加倍，并在成品里写明。

抽检发现判错时：

- 是规则有漏洞造成的（同类会反复出现），改 `rules.md`，重筛受这条规则影响的批次；
- 只是个别看走眼，逐条改正。

没重筛的范围在成品里写明。每次抽检都记下抽了哪些 ID、错了几条、做了什么修正。

## 覆盖率

两种口径都报：

```text
候选集字数覆盖率 = 已读原文字数 / 全部字数已知的候选的字数
决策集字数覆盖率 = 已读原文字数 / 预筛后保留、字数已知的条目的字数
```

已读按实际读到的字数算：只读了关键段落的，只算读到的那部分。字数不知道的条目单列，不塞进分母假装完整。

```bash
python3 <SKILL_DIR>/scripts/coverage.py <任务目录>/ledger.jsonl <任务目录>/screen/*.jsonl <任务目录>/read/*.jsonl
```

脚本按 ID 合并账本和各批结果（后面的文件覆盖前面的同名字段，抽检改判写成单独的文件放在最后），核对每条的决定是否合规、定了级的是否真有读原文的记录，再算两种覆盖率，列出字数未知的条目和最长几篇读到多少。交付前加 `--final`，还没预筛、还没定级的也算不合规。有不合规时退出码非 0。

## 跨篇综合

不先想一个主题再把文章往里塞。先从证据里找能被支持或反驳的论断，再聚类。综合用精读笔记，不回头读原文全文。

每条主线至少回答：

1. 谁在提出或支持它？来源是不是集中在一家厂商？
2. 机制是什么，而不只是现象是什么？
3. 有哪些可以核查的数字、案例或原始证据？
4. 有哪些反例、边界或还没验证的假设？

给主线标证据强度：

- 强：多个独立来源，至少一个一手或可复核的实证，并处理了反证；
- 中：有一手或多个一致的来源，但边界还不充分；
- 弱：单一来源、主要是观点，或有没解决的冲突。

看起来冲突的文章，先看双方完整的论证（笔记不够就回原文读相关段落）；很多“冲突”只是摘要省略了适用的边界。原文之间确实矛盾的，并列写出，各注来源。

## 两种交付

### 周期性导读

回答“这一轮内容对既有判断做了什么”：印证、推进、分叉、扩展还是推翻。建议结构：

1. 结论先行：不超过 3 条；已有总纲时，每条挂到既有母题上，或标明是新母题；
2. 对应总图（已有总纲时）：`母题 | 新证据 | 关系 | 判断`；
3. 必读逐条：真正要摘的内容、对行动的影响、证据层级；已有总纲时写对总纲的新增；
4. 值得知道与收录：收录的列成表，写为什么收、还缺什么、下一步；
5. 反面与未解：反证、没验证的、主动查过的范围；
6. 阅读顺序与分钟预算；
7. 可以直接追加到总纲的句子（已有总纲时）；
8. 下一轮观察信号；
9. 范围账：候选范围、排除名单、只读了摘要的、未评估的、缺口与抽检结果。

### 专题总纲

一次性的大批历史材料，合并成三类内容：

- 论证：主线、机制、证据、反面、边界和强度；
- 清单：可复用的方法、问题、检查表，逐项标出处；
- 判断：来源分层、优先级、缺口和可信度。

## 命名、过程稿与任务目录

- 周期性导读：`📊<信源>导读_YYYY-MM-DD至MM-DD.md`
- 专题总纲：`📚<信源>总纲_YYYY-MM至MM.md`

日期区间是内容覆盖的范围，不是整理日期；信源用稳定的通称。成品写进 `OUTPUT_DIR` 根目录，同名文件不覆盖。

候选索引、逐篇笔记、筛选清单、聚类草稿都是过程稿，最后并进主文档对应的章节，不另外交付。合并前核对候选总量、排除理由、未读原文、覆盖率和结论的证据，是否都还能在主文档里追溯到，别让它们只留在某份过程稿里。

交付后可以在 `.local/baseline.md` 记一笔基准：输入规模、还原的候选数、通读字数、覆盖率、产出规模、误排次数、画像样本量。

交付后不马上清理任务目录：偏好复盘要用账本和各批决定。进度文件里写明复盘要用哪些文件；复盘做完，或用户说不需要了，先确认目录里没有用户的文件，再把整个目录移到废纸篓。只处理本次自己建的目录；失败时保留目录，报告路径和已完成的部分。

## 交付自检

```text
[ ] 候选范围、来源层级和遗漏风险已交代
[ ] 预筛看的不只是标题；只凭标题预筛的范围已写明，抽检已加倍
[ ] 排除理由都来自封闭清单，逐条可回查
[ ] 排除项和“只看摘要”的保留项都抽检过，判错已按规则处理，没重筛的范围已写明
[ ] 必读、值得知道、收录都建立在读过原文上；只读了摘要的单列
[ ] coverage.py --final 没有报不合规；覆盖率按字数报，抓取失败和字数未知的单列
[ ] 主线含机制、数字、反例、来源立场与证据强度
[ ] 成品里的数字、日期（含星期）、图表数据，已对照笔记里的原文原句核对，并随机抽 5 条回原文核对；原文之间互相矛盾的已并列注明来源
[ ] 反面与未解单列，没有只收支持的证据
[ ] 只交一份主文档，过程稿里的信息没在合并中丢失
[ ] 用户的原始材料没被改动
[ ] 拟入表只是提议，没有写表
```
