# 偏好复盘

主对话读这份。只在用户给了采纳反馈（勾选了、说了要哪些）或明确要复盘时做，不是每次交付后的固定步骤。

不凭印象写用户画像。用任务目录里的账本和各批决定，把完整候选集和用户最终采纳的那部分做对比，看：

- 来源板块；
- 主题；
- 内容性质（方法、观点、实测、发布等）；
- 同一对象的多条消息里，采纳了哪条；
- 已接受结论的反对证据，是不是被系统性地漏掉。

时间规律只有在收集机制明确时才能解释：同一批内容如果是一次性倒序浏览的，不能说成几个月来的持续偏好。

结论要附样本量，小样本只当待验证的线索。每次复盘都问一句，或者自己查一下：有没有“回头看觉得不该跳过”的条目；用户确认的原因，升级成带可执行判据的一票保留规则。

写进 `.local/profile.md` 之前，先把要写的结论和规则给用户看，用户同意再写。写完更新 `.local/baseline.md` 里这一期的画像样本量。

复盘做完，任务目录就可以清理了，做法见 triage.md 的“命名、过程稿与任务目录”。
