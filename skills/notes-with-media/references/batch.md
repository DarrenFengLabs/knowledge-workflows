# 多个单元：分派与合并

主对话读这份，子代理不读。宿主不支持子代理时，按同样的步骤一个单元一个单元地做，每个单元只读这个单元需要的文件。

## 开工

1. 按 SKILL.md「开工前」和用户对齐一次，整门课共用。
2. 读进度，确定这次做哪几个单元。进度默认写在总导航末尾的「进度」一节，用户另定了位置就按约定；第一次做这门课时新建总导航，末尾留这一节。
3. 按文件名列出每个单元的转写、手写、图和课件，记进本次任务的临时目录（项目 `.local/paths.md` 里有 `STAGING_DIR` 就放它下面）。文件名上的日期可能不准，子代理会按内容再核对。

## 子代理做什么

每个单元一个子代理，在干净的上下文里做，强调密度不会随篇数下滑。告诉它：

- 读：SKILL.md，本单元的转写、手写、媒体，以及当前的术语表（只读参考，不改）。不读本文件，也不读前面单元的笔记。
- 写：本单元的笔记，写到约定的输出位置；要嵌入的图复制进 `Z_Attachment`。外加一份单元摘要，放本次任务的临时目录，按单元命名，如 `2026-06-04.unit-summary.json`。
- 不改总导航、术语表、资料表这些共享文件，免得并行时互相覆盖。

单元摘要的字段：

| 字段 | 内容 |
|---|---|
| `nav_row` | 总导航里这个单元的一行，各列见下面「合并」 |
| `terms` | 本单元新确认的术语解释和听错词对照 |
| `materials` | 资料，课堂资料和「我的补充」分开 |
| `unplaced_media` | 未读或未归位的媒体：文件名、读出的内容或“未读”、疑问 |
| `doubts` | 要用户判断的存疑，包括日期、归属对不上的 |

## 合并

子代理回来后，主对话按单元顺序依次合并，一次只改一个文件：

- 总导航：按单元排的一张表，列为 文件名 | 真实日期 | 课型/主讲 | 一句话主线 | 关键知识点 | 媒体数 | 备注/日期核对。先读，再追加或更新这个单元的行，不重建。
- 术语表、资料表：先读现有内容，追加到对应位置，保持原格式。
- 进度：每合并完一个单元就更新——做到哪个单元、下一个是哪个、还剩哪些，已确认的文件切分特例，遗留的存疑，未读或未归位的媒体。

一个单元失败只记进进度，接着做别的单元。要用户认领的媒体、要用户判断的存疑，全部做完后一次问。

## 中断后接着做

状态全在文件里：笔记、汇总文件、总导航和进度。上下文被压缩或换了会话，只读进度、总导航和 SKILL.md 就能接着做；开下一个单元前重读 SKILL.md，不凭记忆写。不派子代理、在一个对话里连续做时，靠总导航那几行了解前面讲过什么，不回看前面单元的全文。
