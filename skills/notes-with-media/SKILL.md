# notes-with-media · 转写 + 手写 + 媒体融合整理 Skill

把转写（ASR docx / 纯文本：课堂、会议、讲座、播客、访谈）整理成**看笔记就能替代音频、也替代翻截图**的结构化笔记，逐"单元"（通常一天/一场）产出一份 Markdown，并把你的**手写笔记、截图/照片、课件、资料**融合进去，按需维护总导航、术语表、资料表。

## 配置与事实纪律

若当前项目存在 `.local/reader.md`，写作前读取其中的读者背景；若项目另有课程约定或进度文件，也先读取。输入和输出路径每批不同，始终按 §0 与用户对齐，不从其它 skill 继承路径。

每次任务遵守 [references/source-integrity.md](references/source-integrity.md)。ASR 把网址和产品名听错是常态，拿不准就标记，绝不补成一个“看起来合理”的值。

> **本 skill 与众不同的两条立场**（务必记牢，别套用旧习惯）：
>   1. **你的手写笔记 = 你判定的重点**（§2）。这跟"记了≠重要、只看讲者强调"的老规矩**相反**——这里手写是一等重点信号。
>   2. **截图/照片/课件/资料要"读进正文"并能反向纠正转写**（§6）。

> **关于「一次任务只交一份文档」**：这条规则管的是**过程稿不要拆成多份**。**多单元课程每个单元一份是正常交付，不受该条约束**——20 天课就是 20 份 + 1 份总导航。

## §0 开工前先定（必须，30 秒对齐，别假设）

1. **转写在哪**：目录 + 格式（docx / txt / md）+ 命名规律（含不含日期、一个单元几段）。
2. **输出到哪**：每单元一份 `YYYY-MM-DD.md`（或其它命名）放哪。
3. **手写笔记在哪**：md/html/docx，或**直接是拍纸质笔记的照片**——这是重点信号，先读（§2）。
4. **媒体在哪、怎么排**：截图/照片文件夹、课件（PPT/PDF）目录；文件怎么命名、有没有顺序线索、你有没有在手写里给某张图打过 `〔图N〕` 这种锚点（§6 归位靠这个）。
5. **资料**：老师发的链接/文件，和你自己额外查的——**两类要分开标源**（§6）。
6. **要不要维护汇总文件**：总导航（多篇强烈建议）、术语表、资料表——有就**先读再追加、绝不重建覆盖**。

> **推荐的归档约定（轻，否则你不会坚持）**：一天一个文件夹，东西全往里扔、原始文件名不用改：
> ```
> 2026-06-04/
>   转写/          ASR 的 docx/txt（可多段）
>   手写笔记.md     也可以是 .docx/.html，或直接拍纸质笔记的照片
>   图/            截图+照片全堆这（IMG_001 / Screenshot… 原名即可，顺序≈讲课顺序）
>   课件/          老师发的 PPT/PDF
>   资料.md        链接清单；懒得单独建就把链接写进手写笔记
> ```
> 把约定写进该项目的宿主指令文件（如 `CLAUDE.md` 或 `AGENTS.md`）或进度文件，后续不必反复问。

## §1 核心原则（最高优先级，冲突时以此为准）

1. **覆盖范围由转写决定，强制全覆盖**：转写讲到的点都覆盖，把讲解、论证逻辑、例子写进去，让人不必回听。**绝不因为"手写/媒体里没记"就略过转写讲过的点。**
2. **全覆盖但收一档**：在全覆盖前提下，对废话、重复、口水、铺垫**适当压缩总结**，合并同类，写成通顺讲义段落而非碎条目——避免太长难读。⚠️ **压缩 ≠ 退化**（见原则 5）。
3. **不重复**：同一内容只在一处充分展开，其他地方引用而非重述。
4. **有知识框架，不平铺**：先提炼这个单元的逻辑骨架（几条主线/几个模块、模块间关系），知识点挂在框架下；顶部放"速览"让人 30 秒看懂讲了啥。
5. **强调密度不能塌（最易退化的点）**：`*斜体*`（重点）、`>` 引用块（金句原话）、表格（对比/分级/清单类信息）是**逐句判断的硬活，不是可省工序**。一篇内容充实的笔记通常有数十处斜体、十几处金句引用块、若干表格。每写一段都问三句：这里有没有重点（→斜体）？有没有该原样保留的金句（→引用块）？这段对比/分级信息是不是该用表格？
   - **防退化的正确姿势＝只要标准、不要形态**：别把某篇旧笔记当样板去模仿（样板会变成天花板和枷锁，连结构详略缺点一起复制）；不同课型（实操/纯讲授/分享/问答）本该长得不一样。每篇真正对齐的对象是**当前这段转写本身**。
   - **高密度靠"抽象规则 + 写完量化自检"守**（见 §7 第 5 步），不靠读整篇旧笔记唤醒。

## §2 重点信号 = 你的手写 ∪ 讲者强调（本 skill 的关键立场）

**重要性来自两个来源的并集，两者都覆盖、重叠处最强：**

| 来源 | 含义 | 怎么落到笔记 |
|---|---|---|
| **① 你的手写笔记** | 你**主动判定**的重点（通用场景下你记的就是你认为值得记的） | 命中的知识点**一律纳入正文并充分展开**；你画了记号 / 老师也反复讲的，上 `*斜体*`，优先进「带走三点」 |
| **② 讲者明确强调** | 反复讲、点名说重要/考点/核心 | 同上：正文 `*斜体*`，进速览 |

落地要点：

- **手写是「重点指针」，不是正文本体**：你常只记一个关键词，真正的展开仍**靠转写补全**。规则＝**手写标出在哪、转写填满内容**。
- **覆盖范围仍由转写定**（原则 1，全覆盖优先）：手写**不缩小**范围——你没记但老师讲了的，照样全覆盖；手写只在转写之上**叠加重点**。
- **手写有、转写没有的"偏内容"知识点**（概念、分级表、清单、某个结论）：**必须进正文**，注明来源「手写笔记」，即使转写没展开、即使不标重点。这是全覆盖的延伸。
- **手写里夹着 AI 整理版**（带"核心结论/精彩金句"模板腔）时，那只是参考，不照搬其措辞；你**亲手记**的部分才是重点信号。
- **易错信息冲突**（人名/术语/数字/网址）：两边都可能错，**并列两版进末尾"可信度"栏**，不自动选、不编造——**除非**有截图/课件能坐实（见 §6 信源优先级）。

## §3 格式规范（飞书友好 + 减负）

- **结论加粗**；**金句用 `>` 引用块**；重点（手写/讲者强调命中）用 **`*斜体*`**。
- **结构化信息用代码块或表格**：脑图、流程、路径、对比、清单、媒体清单。
- 标题层级：`##` 栏目 → `###` 主线 → `####` 小节，**不要用 `#` 一级标题**（飞书层级会乱）。
- 不用下划线 `~…~`（飞书不渲染）、不用 `==高亮==`（不显示）。**唯一的正文强调就是 `*斜体*`**。
- 克制使用格式，别过度影响阅读。

### 飞书强调标记生效规则（务必遵守，否则 `*`/`**` 不渲染）
**落笔即遵守，不靠脚本事后兜底。** 写每个 `*`/`**` 时当场把标点/引号/括号甩到标记**外侧**。
飞书（CommonMark）规则：`*`/`**` 的**紧贴侧字符**只要是 ①空格/换行 ②任何全角标点（。，、；：？！…—（）【】「」《》等）③引号（中英文），强调就**失效**、原样显示星号。口诀：**开标记看右侧、闭标记看左侧，紧贴侧必须是"实义文字"。**
正确写法（标点/空格/引号留在标记外）：
- 句末标点移出：`**结论**。` 不是 `**结论。**`
- 括号移出：`**To B**（面向企业）` 不是 `**To B（面向企业）**`
- 引号移出：`"**关键词**"` 或 `**关键词**` 不是 `**"关键词"**`
- 斜体同理；开标记前别留空格
- 整段都是标点/引号时干脆不强调

**脚本只兜底**：落笔写对，写完用 `scripts/check_format.py` 扫一遍，正常应零命中。

## §4 ASR 纠错规则

- 资料名/网址/数字/版本号/人名一律视为**低置信**，按上下文（+截图/课件，见 §6.2）纠正后，**确定的进正文、仍存疑的汇入末尾"可信度"栏 + 术语表**。**绝不替用户编一个看似合理的网址或数字**，详见 [references/source-integrity.md](references/source-integrity.md)。
- **正文里不要散落 `〔低置信〕` 这类括号**——集中到末尾可信度栏。
- 维护术语表：黑话/缩写/中英混说、高频听错词（建项目专属对照表，如某产品名/工具名被听成别的词）。
- 自我更正只留改后版本；前言不搭后语/话题突跳→怀疑丢段并标出；异常通顺的可疑段保持怀疑。

## §5 长跑（一口气做多篇 / 中途会被 compact）的生存法则

- **状态全外化到文件、绝不靠"记得"**：每篇做完立刻落盘（笔记 + 汇总文件 + 总导航 + 进度 memory + 未归位媒体）。被 compact 后只读"进度 + 总导航 + 本 SKILL"就能续。
- **每篇开工前从文件重读**：compact 会压掉密度细节与媒体归位状态，开新一篇若没把握就回读本文件全文。
- **写完量化自检是抗退化最后一道闸**（§7 第 5 步的自检脚本）：即使"忘了"高密度是常态，脚本的数字会把你拉回来——长跑时尤其不能省。
- **减缓膨胀**：不大段回贴转写原文；后续篇靠总导航那几行了解前情，不回看前篇全文。

## §6 媒体处理方案：截图 / 照片 / 课件 / 资料（本 skill 的核心增量）

目标：**让看笔记的人不用再翻截图、不用再开课件**——图里的实质内容变成正文。

### 6.1 处理流水线（每个媒体文件都走一遍）

```
归类 → 读图 → 归位 → 融入正文 → 留痕
```

1. **归类**（视觉扫一眼判断是哪种）：
   - **拍自己纸质笔记的照片** → 当 **§2 的手写重点信号**处理，不是内容信源。
   - **课程内容截图**（PPT 投影 / 工具 UI / 代码 / 图表 / 网页）→ **内容信源**。
   - **课件 PPT/PDF** → **内容信源**（结构化，按页，常常就是老师的大纲）。
   - **资料链接 / 文章 / 分享的文件** → 进「资料」栏，关键内容可融入相关知识点。

2. **读图**（用视觉/抽取把图读成文字实质，不是甩附件）：
   - 幻灯片截图 → 抽要点文字 + 结构；架构/流程图 → 转成文字描述或表格/代码块，保留箭头方向和连接关系（谁指向谁）；代码截图 → 代码块；UI 截图 → 描述关键状态 + 图里可见的**网址/产品名/数字**。
   - 同一张幻灯片的多张截图、连拍 → **自动合并去重**；随动画逐步出现的多张，以最终完整版为准，中间状态若有最终版没有的信息（被划掉的内容、中途演示的数值），在对应处注明。
   - 密集图表、小字、技术图纸：用原始分辨率文件读；看不清时在临时目录的副本上裁切放大局部再读（如 macOS 自带的 `sips`），不改用户原图；仍读不准，按 §6.2 标存疑。
   - 当前模型或智能体看不了图时：列出没读的图，请用户提供文字版；这些图列入「未归位媒体」，不猜内容。
   - 课件：PDF 用可用的 PDF 工具读取；PPT 用 `scripts/extract_pptx.py` 抽文字（图表/示意图仍靠截图补）。

3. **归位**（把图挂到正确的知识点上，三级降级，**绝不硬猜**）：
   - ① 你在手写里给它打了锚点（`〔图1〕`/`[图]`）→ **直接确定**。
   - ② 没锚点 → **按图的内容**匹配到对应转写小节（默认主力）。
   - ③ 内容也难判断 → 用当天截图的**顺序**兜底（顺序≈讲课顺序）。
   - ④ 实在归不进去 → 进末尾「**未归位媒体**」清单**问用户**，不瞎放。

4. **融入正文**：图的实质变成对应小节里的正文 / 表格 / 代码；原图位置留一个指针 `〔截图：原文件名〕`（理由见 6.3）。

5. **留痕**：当天末尾一张「**媒体清单**」表，既给用户核对我放得对不对，也当**导飞书时的贴图清单**：

   | 文件名 | 归入哪节 | 读出的要点（一句话） |
   |---|---|---|
   | Screenshot…14.32 | ②-主线一-定价 | 三档定价 9/29/99，年付 8 折 |

### 6.2 ⭐ 信源优先级：截图/课件反过来纠正转写

对**易错事实**（网址、产品名、版本号、人名、屏幕上的代码/数字），信源可信度排序：

> **截图 / 课件原件 ＞ 手写笔记 ＞ 转写（ASR）**

所以一张写着「Claude Code」的截图，能把转写里的「克劳德扣的」**直接坐实纠正**，把该项从"可信度栏存疑"**升级为正文确定内容**（并把对照写进术语表）。这是媒体最大的价值。

> 但**视觉也会读错**：图模糊 / 反光 / 半遮挡时，按事实纪律（见 [references/source-integrity.md](references/source-integrity.md)）处理——读不准的网址/数字**标存疑进可信度栏**，别猜一个看似合理的。

### 6.3 飞书里图怎么呈现（默认方案）

**硬约束**：飞书粘贴 Markdown 时，本地图片路径 `![](./x.png)` **不会渲染**（它读不到你电脑里的文件）。所以：

- 正文**只写从图里抽出的文字实质**（这才是"看笔记替代翻图"，图丢了也看得懂）；
- 原图位置留指针 `〔截图：文件名〕`；
- 用户导飞书时走到指针，照「媒体清单」把对应图**手动拖进去**。

> 二期可选（默认不做）：若用户要自动嵌图，可用 lark-drive 把图传飞书云空间换成真 URL 再嵌入。先走手动。

### 6.4 资料补充：课堂 vs 自查，强制分开标源

- **课堂资料**（老师发的链接/课件/文件）：进「资料」栏 + 关键内容融进相关知识点，不加注。
- **你自己额外查的**：**必须标 `（我的补充，非课堂）`**，绝不和"课堂讲的"混淆。这是"不编造"红线的延伸。

## §7 工作流程（每个单元一份文件）

### 1. 抽取转写 / 课件
docx 转写用 `scripts/extract_docx.py`（标准库，不依赖 pandoc/python-docx）；课件 PPT 用 `scripts/extract_pptx.py`；PDF 用可用的 PDF 工具读取。
```bash
python3 scripts/extract_docx.py "转写/2026_06_04_*.docx" --sep -o /tmp/day.txt   # 一个单元多段
python3 scripts/extract_pptx.py "课件/第N讲.pptx" --notes > /tmp/ppt.txt          # 课件抽文字（带备注）
```
转写排版**不统一**——有的带"说话人N + 时间戳"，有的是连续长段。**说话人和具体时间均不可信、不要采用**；按内容区分讲者，需追溯时让用户去原文搜关键词。

### 2. 分批读，别一次塞满上下文
单段可能 500+ 段、近 10 万字符。用 `sed -n '起,止p' /tmp/day.txt`（每批约 200 段）分批读，处理一批就**边做边写盘**。读完即提炼，**不要把转写原文大段回贴进输出/对话**。

### 3. 先读"叠加层"抽信号，再以转写全覆盖
**顺序**：先读手写笔记（§2）和媒体（§6）——
- 从手写抽：①人名/工具名/术语/网址的正确写法（→术语表）；②**重点信号**（命中的点要进正文、倾向强调）；③图锚点 `〔图N〕`。
- 从媒体抽：归类 + 读图 + 待归位清单；记下哪些图能**纠正转写易错项**（§6.2）。
然后**以转写为骨架做全覆盖**，把手写重点叠上去、把图的实质融进对应小节、用术语表+截图纠正听错词。

### 4. 按模板整理并写盘（模板见 §8）
产出到约定输出文件。维护术语表/资料表的，**先 Read 现有内容、追加到对应位置、保持原格式，绝不整体重写或覆盖**。

### 5. 写完量化自检（防退化托底，别省）
跑 `scripts/check_format.py 你的笔记.md`：查飞书强调标记违规，并报斜体数/金句块数/表格数/字数。用**相对判据**看（数字与内容量是否匹配、有没有整篇滑成"列点平铺"），偏少就回去补。**目标：强调标记违规 0。**

### 6. 多篇时更新总导航 + 记进度
- **总导航**：一张按单元排的表（文件名 | 真实日期 | 课型/主讲 | 一句话主线 | 关键知识点 | 媒体数 | 备注/日期核对）。每做完一篇追加/更新该行，先 Read 再改、不重建。
- **记进度**：把"做到哪篇/下一篇/剩余/遗留存疑/未归位媒体"写进项目 memory，保证被 compact 也能续。

## §8 笔记结构模板

```
# YYYY-MM-DD（第N天 / 场次标题）笔记
> 形式/来源：本单元 N 段转写 + 手写笔记 + M 张图/课件。说话人/时间戳不可信、已忽略。
> 听错词与术语见《术语表》，资料见《资料表》。
> ⚠️ 日期/内容核对（若文件名日期可疑）：以内容为准的判断 + 特例说明。

## 🗺️ 速览
（代码块画树状脑图：几条主线/模块，一句话主线）
> 带走三点：①… ②… ③…   （30 秒看全貌，与正文不重复；优先放手写/讲者强调命中的点）

## ① 主干知识点
（按主线组织：### 〈主线一〉…  下设 #### 小节，讲义级展开。
 关键结论段内**加粗**，不单列"关键结论"栏；金句用 > 引用块；对比/分级/清单用表格；

 案例/讨论/随机事件并入最相关知识点段落，不单独分类。）

## ② 行动清单（有则写，- [ ] checkbox）

## ③ 资料与链接（有则写；课堂资料 / 我的补充 分开标；与资料表呼应不重复正文细节）

## ④ 媒体清单（有图/课件则写：文件名 | 归入哪节 | 读出的要点；导飞书时按它贴图）

```
末尾几栏编号不固定，内容到第几节就是第几节。

**人名写法**：正文优先用本名；拿不准的人名直接用「老师/讲者/嘉宾」等角色代称，**不在"可信度"栏列人名清单**（人名/听错词对照统一维护在术语表）。

## §9 日期/归属校验（多日单元尤其重要）

**文件名上标的日期/归属可能错，一律以内容为准、不盲信。** 用户也可能自己重命名/重新归并文件、段数会变。开工前先 `ls 目录 | grep 该日` 看**当前**段数，再用内容交叉判断真实归属，对不上就在笔记顶部 ⚠️ 标出 + 在总导航备注列说明。把已确认的切分特例记进项目 memory，重做前先查、别按文件名回退。
