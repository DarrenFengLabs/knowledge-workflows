# 上传存飞书

剪藏读完、决定以后写作时可能要回来查证或引用的，用户会拖进 `存飞书/`；攒几篇后说一句“上传存飞书”，由这个 skill 传进飞书存档，本地那份删掉。这样同一篇原文只留一份，飞书里能全文搜索。用户那边怎么判断、什么时候拖进来，写在用户主库的《个人系统规范》里；这个 skill 只管上传和核对。

两条不变量：

- **没核对通过就不删本地。** 飞书里建成功、标题和位置对、正文逐行都找得到、图片数一致，四项全过才移进废纸篓。任何一项不对都保留本地，列给用户看。删本地只由脚本移进废纸篓；脚本挪不动的交给用户手动删，不改用 `rm`、Finder 脚本或关沙箱去绕（2026-11-18 用户定）。
- **只建不删。** 不删、不改飞书里已有的文档；重跑时遇到同名文档不重复上传，只拿它和本地核对。传错了由用户在飞书里手动删。

## 配置与授权

配置在仓库根目录 `.local/clip-archive.json`（Git 忽略）。缺少时问用户，不猜路径和 token：

| 键 | 含义 |
|---|---|
| `src_dir` | 待上传目录，即 0Temporary 的 `存飞书/` |
| `vault_dir` | 0Temporary 库根目录，用来找 `![[粘贴图]]` 这类嵌入图片 |
| `staging_dir` | 每次运行的工作目录和报告放这里（本地、不同步的目录） |
| `space_id` | 知识库「全文剪藏」的 space_id |
| `long_node` / `short_node` | 「3单篇」/「4短篇」的节点 token |
| `short_max_words` | 多少字以下算短篇，默认 800 |
| `test_folder` | 可选。云空间测试文件夹的 token，改脚本后试跑用，见 [references/maintain.md](references/maintain.md) |

开工先按 [references/lark-auth.md](references/lark-auth.md)「标准流程」第 1 步检查授权，要重新授权就照那份做。

## 流程

1. 运行 `python3 scripts/archive_to_lark.py run`（路径相对本 skill 目录）。不用先问用户：说“上传存飞书”就是要传。每篇约 10–30 秒；篇数多时先说一声大概要几分钟，并把命令放到后台运行或把命令时限设够（宿主默认的时限常常只有一两分钟，如 Claude Code 默认 2 分钟），免得跑到一半被掐断。万一断了，直接重跑：已传的会按同名核对，不会重复上传。
2. 读脚本打印出的 `report.md`，向用户汇报：传了几篇、分别进了哪个文件夹、哪些已删本地。报告里「要你手动删的本地文件」原样列给用户；没删的逐篇说原因和要用户做什么（见下）；「没处理的文件」（不是 Markdown 剪藏的，如 PDF）也列给用户，提醒这些由用户手动归档。不读剪藏全文，报告里的信息够用。
3. 退出码 2 表示脚本停下了：缺配置、授权失效，或读不到飞书目录。开头就停的，一篇都没传；传到中途因授权失效停的，前面几篇已经传完、可能已删本地，脚本会打印这次的报告路径，照第 2 步汇报。补好配置或重新授权后重跑即可。

## 上传后飞书里是什么样

标题用文件名（不含扩展名），不改名。属性区只留来源链接、作者、发布时间，转成开头的「背景信息」小表。双语剪藏英文原文的灰色字，在飞书里仍是灰色。图片都传进飞书文档；没传上的，网络图留成“〔图片未上传〕”加原链接，本地图留成“〔图片缺失：文件名〕”。文件夹形式的剪藏（`index.json` 加 `assets/`）当一篇处理，删本地时整个文件夹一起删。

## 没删本地时怎么办

| 报告里的原因 | 怎么处理 |
|---|---|
| 图片数不符 / 图片缺失或下载失败 | 飞书文档已建好，缺的图留了占位（见上一节）。列给用户定：补图后在飞书手动删掉这篇再重跑，或接受现状、手动删本地 |
| 有几行文字在飞书里没找到 | 报告列出了这些行，多半是特殊符号被飞书当成格式吞掉。列给用户，说明可能是哪个符号，建议补转义规则；用户同意后按 [references/maintain.md](references/maintain.md) 改脚本，再请用户手动删掉飞书里那篇后重跑 |
| 飞书里已有同名文档，但核对不一致 | 最常见的是上次就没核对通过、飞书那篇没删就重跑了；也可能是用户以前手动传过，或改过飞书那份。列给用户定，不自动处理 |
| 本地要手动删（macOS 不让挪） | 在 Obsidian 里打开过的文件常带 `com.apple.macl` 属性，只有特定应用能挪动它，脚本的 `trash` 会被拒（Code=513）。按上面的不变量，把报告里的清单原样交给用户，在 Obsidian 或 Finder 里手动删 |
| 建文档出错 / 回读失败 | 看报错。网络或限流问题稍后重跑即可 |

要改脚本（转义规则、核对规则）或试跑时，先读 [references/maintain.md](references/maintain.md)。
