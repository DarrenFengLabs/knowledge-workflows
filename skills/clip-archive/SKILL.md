# 上传存飞书

剪藏读完、决定以后写作时可能要回来查证或引用的，用户会拖进 `存飞书/`；攒几篇后说一句“上传存飞书”，由这个 skill 传进飞书存档，本地那份删掉。这样同一篇原文只留一份，飞书里能全文搜索。流程的来龙去脉见用户主库的《个人系统规范》4.5 节和附录 A。

两条不变量：

- **没核对通过就不删本地。** 飞书里建成功、标题和位置对、正文逐行都找得到、图片数一致，四项全过才移进废纸篓。任何一项不对都保留本地，列给用户看。核对通过但 macOS 不让挪的，由用户手动删（2026-11-18 用户定），不绕权限。
- **只建不删。** 不删、不改飞书里已有的文档；重跑时遇到同名文档不重复上传，只拿它和本地核对。传错了由用户在飞书里手动删。

## 配置与授权

配置在仓库根目录 `.local/clip-archive.json`（Git 忽略）。缺少时问用户，不猜路径和 token：

| 键 | 含义 |
|---|---|
| `src_dir` | 待上传目录，即 0Temporary 的 `存飞书/` |
| `vault_dir` | 0Temporary 库根目录，用来找 `![[粘贴图]]` 这类嵌入图片 |
| `staging_dir` | 每次运行的工作目录和报告放这里（本地、不同步的目录） |
| `space_id` | 知识库「全文剪藏」的 space_id |
| `long_node` / `short_node` | 「3单篇」/「4短篇」的节点 token |
| `files_node` | 「5文件」的节点 token（手动归档原始文件时用，脚本不用） |
| `short_max_words` | 多少字以下算短篇，默认 800 |

开工先跑 `lark-cli auth status --json`。用户身份不是 `ready`/`needs_refresh`、或报缺权限时，按 [references/lark-auth.md](references/lark-auth.md) 重新授权。项目说明要求几个 skill 的权限清单合并后一次申请时，以项目说明为准。

## 流程

1. 运行 `python3 scripts/archive_to_lark.py run`（路径相对本 skill 目录）。不用先问用户：说“上传存飞书”就是要传。篇数很多时（几十篇）先说一声大概要几分钟，每篇约 10–30 秒。
2. 读脚本最后打印的 `report.md`，向用户汇报：传了几篇、分别进了哪个文件夹、哪些已删本地；报告末尾「要你手动删的本地文件」原样列给用户；没删的逐篇说原因和要用户做什么（见下）。不读剪藏全文，报告里的信息够用。
3. 退出码 2 是配置或授权问题，整批没跑：按提示补配置或重新授权后重跑。

脚本每篇做的事：属性区只留来源链接、作者、发布时间，转成开头的「背景信息」小表；图片全部先在本机备好再上传（飞书服务器下载不了推特等境外图床，公众号图床要带来源头）；字面的 `<`、单个 `~` 加转义，相邻格式之间的空格换成不换行空格，免得被飞书吞掉；双语剪藏的英文原文（新写法是 `#8f959e` 灰色字，旧剪藏是 `<small>`）转成飞书的灰色字；标题用文件名（不含扩展名），不改名。文件夹形式的剪藏（`index.json` 加 `assets/`）当一篇处理，删除时整个文件夹一起删。

## 没删本地时怎么办

| 报告里的原因 | 怎么处理 |
|---|---|
| 图片数不符 / 图片缺失或下载失败 | 规范要求先不删、列给用户看。飞书文档已建好，缺的图在文中留了原链接或“〔图片缺失〕”。用户决定：补图后在飞书手动删掉这篇再重跑，或接受现状、手动删本地 |
| 有几行文字在飞书里没找到 | 报告列出了这些行。多半是特殊符号被当成格式吞掉；把例子补进脚本的转义规则和单测，再请用户手动删掉飞书里那篇后重跑 |
| 飞书里已有同名文档，但核对不一致 | 可能是用户以前手动传过、或改过飞书那份。列给用户定，不自动处理 |
| 本地要手动删（macOS 不让挪） | 在 Obsidian 里打开过的文件常带 `com.apple.macl` 属性，只有特定应用能挪动它，脚本的 `trash` 会被拒（Code=513）。这是用户选定的做法：把报告里的清单交给用户，在 Obsidian 或 Finder 里手动删。不要改用 `rm`、Finder 脚本或关沙箱去绕 |
| 建文档出错 / 回读失败 | 看报错。网络或限流问题稍后重跑即可 |

## 改脚本时

- 纯文本处理（属性区、转义、图片引用、字数、正文核对）有单测：`python3 scripts/test_archive_to_lark.py`。改转义或核对规则时先补一条复现问题的样例。
- 端到端试跑用测试文件夹，本地不删：`run --test-folder <云空间文件夹 token> --item <剪藏副本>`。试过的样例类型：推特图床、公众号图床、文件夹形式剪藏、`![[粘贴图]]` 缺图、带 `<small>` 的旧双语稿（转成灰色字）、6 万多字的长稿、短篇、网页剪藏插件的属性区。
- 飞书 Markdown 导入的已知行为（2026-11-18 实测，`docs +create --doc-format markdown`）：不认识的尖括号内容被当成标签删掉；单个 `~` 变删除线；两个相邻格式之间的空格被吞；`<small>` 等飞书不支持的 HTML 标签去掉标签、保留文字（报告里会出现“Unsupported tag”提示，不影响核对）；`<span text-color="gray">` 灰色字生效，里面的加粗、下划线照常；`<span style="color:…">` 的颜色会丢；`$100` 这类金额原样保留；境外图床的网络图片飞书服务器下载失败。
